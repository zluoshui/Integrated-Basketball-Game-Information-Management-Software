# 操作流程

## 赛事管理

用户通过“赛事管理”完成赛事创建、导入、切换、修改和导出。

- 创建赛事：输入赛事名和仅由英文字母、数字组成的赛事 ID。
- 导入赛事：选择外部结构化赛事目录，软件校验 `competition.json` 和 `basketball.db` 后复制到本机管理目录。
- 切换赛事：只能从已导入赛事列表中选择。
- 修改赛事：可修改赛事名和赛事 ID；修改 ID 后，旧 ID 的日志不再属于当前赛事。
- 导出赛事：导出完整结构化目录，用于复制到其他设备，再由另一台设备导入。

## 球员与队伍

球员资料库支持新增、编辑、停用、搜索、照片和自定义字段。已有比赛事件引用的球员不应物理删除，只能停用，以保持历史比赛可复核。

队伍支持新增、编辑和停用。停用队伍时需要确认，并提示是否已经被比赛使用。

## 比赛准备

比赛准备阶段创建比赛、选择主队和客队、设置所有参赛球员、球衣号和首发。

准备页通过“准备比赛”下拉框独立选择要编辑名单的比赛。切换准备比赛不会强制改变记分台或比赛日志当前查看的比赛。创建新比赛后，只自动选中准备页下拉框中的新比赛。

开始比赛前必须校验：

- 已选择主队和客队。
- 双方参赛名单不为空。
- 首发球员是参赛名单的一部分。

赛中或赛后修改参赛人员必须走审计修改入口，填写操作人和备注，并记录审计事件。

## 记分台

记分台用于实际比赛，并通过“记分比赛”下拉框独立选择正在记分的比赛：

- 控制节次和倒计时。
- 启动、暂停、继续、重置本节。
- 记录比分和球员个人技术统计。
- 显示双方当前场上球员。

当前主操作逻辑是先点击场上球员，再点击事件按钮记录得分、犯规、篮板、助攻、抢断、盖帽、失误或暂停申请。

普通技术统计事件只应在比赛运行状态记录。换人只应在暂停状态执行。

记分台选择的比赛与准备页、日志页互不强制同步。倒计时和记分操作只作用于当前记分比赛。

## 换人

换人流程：

1. 比赛进入暂停状态。
2. 在场上球员区域选中要换下的球员。
3. 点击“替换”。
4. 从同队候补球员中选择换上球员。
5. 确认后更新当前场上状态，并自动追加 `Substitution` 事件。

换人事件不影响比分和个人技术统计，但必须出现在比赛日志、CSV 和结构化 JSON 中。

## 比赛日志

比赛日志页展示当前赛事的历史比赛，按创建时间排序。历史比赛表本身就是本页的比赛选择器。

- 单击或双击历史比赛行：只切换本页下方统计和事件流水到对应比赛，不影响准备页与记分台的选择。
- 勾选导出复选框：用于批量导出结构化 JSON。
- 没有勾选时：默认导出当前日志页查看的比赛。
- 导入比赛日志：只允许导入当前赛事 ID 的日志，重复比赛 ID 自动跳过。

CSV 仍作为人工查看报表，不作为后续导入的数据源。

## 备份与导出

数据库备份保存在当前赛事工作区的 `backups/`。备份文件名需要避免同秒重复点击冲突。

报表和结构化日志默认保存到当前赛事工作区的 `exports/`，用户可预设导出位置。点击导出 CSV 时直接导出到设置位置，不再每次重新选择。
